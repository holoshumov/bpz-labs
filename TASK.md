## Умова (від викладача)
> Роздивитись основні методи авторизації.
> Викачати репозиторій з лекціями https://github.com/Kreolwolf1/auth_examples.
> Запустити кожен з 3 аплікейшенів та зробити скріншоти запитів до серверу.
> Для отримання максимального балу: модифікувати token_auth аплікейшен змінивши токен на JWT.

Оцінювання: основне завдання 7 б., додаткове (JWT) 3 б., відеозахист 2 б.

## Що вже є в цій папці
Копія репозиторію з доданими файлами:
- `basic_auth/`, `forms_auth/`, `token_auth/`: оригінальні застосунки (не змінювати).
- `token_auth_jwt/`: **готова** JWT-версія token_auth (`jwt.js` — HS256 на вбудованому `crypto`, `index.js` — сервер, `index.html` — сторінка, що шле `Authorization: Bearer <jwt>` і показує payload). Логіка `jwt.js` уже протестована: валідний токен приймається; невірний секрет, підмінений payload, прострочений токен і `alg: none` відхиляються.
- `package.json`: залежності та скрипти `npm run basic|forms|token|jwt` (усі на порту 3000, тому запускати по одному).
- `requests.sh`: curl-сценарії для кожного застосунку (`./requests.sh basic|forms|token|jwt`).

Відомий баг оригіналу: у `forms_auth` і `token_auth` в `/api/login` після `res.json(...)` немає `return`, тому далі виконується `res.status(401)` і в консолі з'являється `ERR_HTTP_HEADERS_SENT`. На роботу це не впливає. Оригінали НЕ виправляти, лише згадати в нотатках (це гарне питання для захисту).

## Що треба зробити
1. Перевір, що є Node.js ≥ 18 (`node -v`). Якщо нема — `brew install node`.
2. `npm install` у корені папки.
3. Для кожного з 4 застосунків (basic → forms → token → jwt) по черзі:
   - запусти сервер у фоні, збережи його консольний лог у `evidence/<app>_server.log`;
   - виконай `./requests.sh <app>` і збережи вивід у `evidence/<app>_requests.txt`;
   - зупини сервер.
   Перевір, що всі очікувані коди відповіді правильні (401/200 тощо). Якщо щось не так — виправ і поясни.
4. Для JWT додатково перевір: старт з `JWT_SECRET=інший` → токен, виданий раніше, має відхилятися.
5. Склади `evidence/SCREENSHOTS_CHECKLIST.md` — покроковий список скріншотів, які студент має зробити САМ (браузер + DevTools → Network; термінал з `requests.sh`): для кожного застосунку що відкрити, що натиснути, що має бути видно на скріншоті. Для basic_auth: логін DateArt / 2408 у вікні браузера + заголовок `Authorization: Basic ...` у Network. Для forms: cookie `session` у Network/Application. Для token і jwt: заголовок `Authorization` у Network, для jwt — розкодований токен (можна на jwt.io).
6. Склади `NOTES.md` для звіту та захисту:
   - як працює кожен з 4 методів (хто зберігає стан, що передається в кожному запиті, слабкі місця: Basic = base64 без шифрування, сесія в файлі, uuid-токен без терміну дії тощо);
   - що змінено для JWT і чому (stateless, підпис HMAC-SHA256, exp, Bearer, захист від alg=none, timingSafeEqual);
   - 8–10 ймовірних питань на захисті з короткими відповідями (JWT vs session, чому payload не секретний, як відкликати JWT, HS256 vs RS256, де зберігати токен на клієнті, XSS/CSRF тощо).
7. Git: `git init`, `.gitignore` (node_modules, sessions.json, .DS_Store), коміт. Якщо є `gh` і студент залогінений — створи публічний репозиторій `bpz-labs` (або підпапку `lab1` в ньому) і запуш. Посилання на GitHub знадобиться у звіті та для РГР. Якщо `gh` нема — залиш інструкцію в NOTES.md.
